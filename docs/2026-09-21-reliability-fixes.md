# 店铺场景选品：可靠性修复

基准提交：`a9ceb60cecff219dd06f03875f92fb68a36edfab`。补丁编号：`store-reliability-a9ceb60-v1`。

## 产品边界

仍是一个完整产品：上传店铺资料 → 分析商品与场景机会 → 匹配公司产品库 → 选择主 SKU → 导出供现有上架流程使用。

不增加通用需求输入框，不把店铺分析和向量检索拆成要求运营自行选择的独立入口，不限定铺货店。不修改四路检索、融合权重、候选数量、相关性阈值、模型供应商、库存数量公式、原始商品库或已有 SKU 排除规则。

## 已实现的修复

1. **路径缓存失效**：商品资产与双语向量读取以文件身份、大小、纳秒修改时间及 SQLite WAL 状态区分版本；文件替换、删除或 WAL 写入不复用旧缓存。加载过程中检测变化，有限重读；持续变化则停止发布。向量数据库加载时开启一致的 SQLite 读事务。
2. **扩写输入输出对齐**：按原始场景名与中英文商品名精确对应。缺失、重复、改名或类型错误的输出使用原商品词，不丢失输入需求。原始身份不依赖模型生成的新 ID。额外的模型商品不能替换原请求。
3. **扩写字段校验**：扩写必须为字符串数组；不会把字符串拆成字母。规范化、去重、长度上限仍保留。扩写服务异常时可降级使用原始中英文商品词，不无限重试或悄悄增加付费调用。
4. **库存来源固定**：结果记录实际读取文件的 SHA-256、文件修改时间及读取时间。导出说明使用结果自带来源，不用导出当下的文件时间为旧数量背书。历史结果缺失来源时明确写“未记录”。文件时间不冒充业务库存截至时间。
5. **批次清单与断点续试**：场景商品按独立批次保存，以完整清单原子发布。读取校验来源、顺序、文件身份和内容摘要，不再扫描目录合并旧 JSON。同一来源及参数的失败批次可复用已成功场景，只重试缺失部分。
6. **模型复核失败不当作通过**：DeepSeek 必须明确返回 `unrelated` 数组；`{}` 不是“全部相关”。概率仅接受有限的 0–1 数字，不接受布尔值、NaN 或越界值。无有效复核的候选保留为未确认，不误删。
7. **缓存与分片异常**：损坏的复核缓存不会变成永久假成功；验证后才缓存。DeepSeek 分片异常保留其他有效分片，失败分片保留为未确认并记录提示。输出截断不当成完整复核。
8. **恢复原始排序**：关闭复核时，无论此前是否删除过候选，都按原始召回顺序恢复；重复恢复幂等。复核前先把恢复结果写回，异常时界面与导出不会继续读取旧的复核标记。
9. **同店任务保护**：重复提交相同活动任务返回原任务；不同参数不覆盖活动任务。新增单机文件锁，参数按任务冻结。失败、完成、排队取消均释放锁。不是分布式任务系统。
10. **补充结论失败隔离**：场景商品完成后提供有明确“补充分析未完成”提示的结构化结果。扩写读取场景商品而不是依赖经营结论的长文本。补充分析失败时仍可继续 SKU 匹配；不会伪造经营建议。
11. **库存条件不暗中放宽**：明确要求只看有货时，库存未知则报出未能核验，不能把未知候选当作满足现货条件。全候选模式下保留未知状态。
12. **空结果语义**：记录“召回窗口内没有候选”和“本次候选中无目标国家库存”的差别，不把有限 Top-N 结果宣称为全库不存在。此补丁未增加现货专项召回或改变召回数量。

## 修改范围

修改 8 个源码文件；新增公共可靠性辅助模块、回归测试与本说明。前端布局、参数卡片文案和 ADO/ADG 的数据接入**不在本补丁中实现**，避免把可靠性修复混成未经确认的产品重构。

## 验证与仍需验证的边界

附带离线测试执行替换后的函数，使用真实文件系统、SQLite/WAL、NumPy，以及明确的网络/模型/流程边界测试替身。它不是完整仓库集成测试，也没有访问生产商品库、Windows 运行机、模型 API 或付费服务。

补丁工具按原文件 Git blob SHA 校验，先生成完整备份与差异，逐个替换函数定义，保留未改动源码。仓库原文件有本地修改时拒绝覆盖，无强制覆盖选项。安装后必须在原项目 Python 3.12 环境运行新增测试及原有完整测试。

独立发布的商品数据库与向量数据库之间没有共同发布版本。本补丁可以检测读取过程中的变动，不能证明两个各自静止的数据库属于同一业务批次；更新器仍应完成两侧发布后再运行检索。历史产物不存在可追溯批次时不伪造来源；不兼容或不完整历史场景须重新生成。

相同标题不保证实际商品相同；场景相关性不是规格、合规、利润或每个子款可上架的保证。未设置自动上架。多用户权限、分布式锁、磁盘故障、强制进程终止期间的完整多文件事务及真实模型准确率不作通过声明。
