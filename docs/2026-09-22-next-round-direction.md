## 二、逐条说清楚要改什么

### 1. 去掉 ADO / ADG

现在这两个数在上传页填、在报告里显示。要拆掉的地方：

- 上传页的两格输入和那句提示
- 报告里「经营数据依据」上面那一条（ADO / ADG 两个大数字）
- 后台存这两个数的字段、传给模型的那段文字

**销售数据本身留着**——截图里读到的「月销 411」这类商品销售记录不动，那是判断主力产品的依据，也是现在报告里唯一真正有信息量的部分。去掉的只是那两个需要人工手填的全店指标。

一个副作用要提前说：已经跑过的店，销售数据和 ADO/ADG 存在同一个文件里。去掉字段等于那个文件改版，老店要重新跑一次识别才有销售依据。现在只有测试店，可以接受。

### 2. 「写店铺结论」挪到「生成使用场景」前面

现在的顺序是：识别商品 → 应用排除名单 → **生成场景 → 列商品 → 写店铺结论** → 扩写词 → 找商品 → 复核。

改成：识别商品 → 应用排除名单 → **写店铺结论（含产品结构、人群、策略）** → 生成场景 → 列商品 → 扩写词 → 找商品 → 复核。

为什么这个顺序才对：主力产品得先定，场景才能围绕它来写。现在反过来了——场景先自由生成，结论再事后总结，主力产品就成了摆设。

要动的地方：
- 写结论那一步的提示词要重写（现在它的开头就是「场景和每个场景的商品已经定好了」，得改成「先定这家店的产品结构、主力产品和人群策略」）
- 生成场景那一步要接上结论（现在它只看商品线索）
- 报告和相关文件的摆放顺序跟着变

代价要说清楚：结论写的时候还看不到场景，所以「未来产品结构的推进顺序」会写得更粗。我认为这是对的——先有方向再有场景本来就是目的。

### 3. 报告五节：改成一条链，不再互相重复

你把这条交给我按跨境选品的眼光看，我说我的判断。

**现在的问题不是写得少，是五节在说同一件事。** 具体是：

- **店铺画像**在复述商品清单，和「当前产品结构」重了——两段都在讲「这家店卖什么」。
- **当前产品结构**只描述构成，不说谁在赚钱。经理看完知道店里有烤炉、有帐篷，不知道哪几个是命根子。
- **未来产品结构**是从零空想出来的，和当前结构没有因果关系——它没说明这个方向是**从哪个主力产品长出来的**。
- **人群**只写年龄、性别、动机，说完就完了，不落到「所以还该补什么货」。
- **运营策略**和「未来产品结构」「人群」互相抄，经常是同一句话换个说法。

**改成一条链：每一节只回答一个问题，后一节必须踩在前一节的结论上。**

| 部分 | 只回答 | 谁在看 |
| --- | --- | --- |
| 店铺画像 | 这是一家什么店（一句话定位） | 没见过这家店的人，30 秒读完 |
| 当前产品结构 | **钱从哪来**（主力产品点名 + 依据） | 决定补货、砍货的人 |
| 未来产品结构 | **往哪长**（2–3 个方向 + 为什么是它） | 开新品选品会的人 |
| 人群 | **谁买，因此还会要什么** | 定投放和详情页的人 |
| 运营策略 | **下一步做什么，看哪个数** | 具体执行的人 |

**主力产品就落在「当前产品结构」这一节**——它回答的本来就是「现在靠什么」。不新增字段、不新增模块，改的是提示词：要求它点名 3–5 个主力产品，每个带依据（截图里看到的销量、出现在几张主图上、有多少货），其余的同类一句话带过。

**三条硬规矩**（写在提示词里）：

1. **一个判断只准出现在一节里。** 后面那节不许把前面的话换个说法再说一遍。
2. **每条判断必须挂一个具体锚点**——商品名、截图里的销量数字、出现在几张图、有货多少。没有锚点的形容词（「市场潜力大」「需求旺盛」）一律不写。
3. **后面每一节要说明它踩的是前面哪一条。** 未来产品结构的每个方向要写清是从哪个主力产品长出来的；每条策略要绑到一个方向或一个人群。

「核心结论」那一块是摘要，摘要重复下面的内容是正常的，规矩只管五节之间。

顺带把「当前产品结构」和「店铺画像」的分工切干净：画像是**定性**的（什么店、卖给谁、是铺货还是垂直），产品结构是**定量**的（哪几个品在赚钱）。别再互相抄。

### 4. 导出重做

这是经理直接看的东西。

**主 SKU sheet（图一的要求全在这里）**：一个场景一组列，从左到右排开；组内一格一个主 SKU，不塞在同一个单元格；组内按有货数量从多到少；同一场景里不重复。

```
        A 场景：庭院烧烤                      B 场景：周末露营
        主SKU     名称            泰国有货    主SKU     名称            泰国有货
        1A0023    不锈钢折叠烤炉    128        1B0031    便携气炉        64
        1A0087    烧烤工具套装      56         1B0045    露营灯          31
        1A0112    炭夹              22         1B0072    折叠桌          18
                                               1B0090    保温箱          7
```

好处是经理选中 A 那一列的主 SKU，直接复制就能贴进 ERP。现在一格里塞一长串换行，复制出来是乱的。

**子 SKU sheet（新增）**

你问要不要一行一个。**要一行一个**，理由就是经理否掉主表那个「一格里塞一串」的同一个理由：一格里塞一串，就没法按有货数量排序，也没法整列复制——而这张表的用途正好就是要看谁有货。

- **一行一个子 SKU**，按主 SKU 分组，组内按有货数量从多到少
- 列：主SKU / 主SKU名称 / 子SKU / 子SKU名称 / **泰国有货数量**（按这家店的国家写）/ 用在哪个场景
- **子款全列，这个国家没货的写 0**——不预筛，有货的一排序就浮到上面了，经理自己在 Excel 里筛
- 产品库里查不到子款记录的主 SKU，列一行并注明，免得表看起来漏了这个货号

**店铺概况 sheet**：改成以产品结构（含主力产品）打头，把 ADO/ADG 拿掉。

**库存那一列的国家名**：现在列头写「目标国家有货数量」，页面上写「TH 可发 6」。都改成**国家名**——「泰国有货数量」「泰国 可发 6」。前端已经有一份 PH/TH/VN/MY 到中文名的对照表（上传页在用），挪到共用位置即可；导出那边也要加一份。

**口径说明 sheet**：保留。哪个库存文件、什么时候读的、参数是多少，这些还得在。

### 5. 导出前的选择：三层都能勾

现在只有 SKU 一个勾。改成三层：

| 层级 | 勾上是什么意思 |
| --- | --- |
| 场景 | 这个场景下所有商品全选 |
| 商品角色 | 这个商品在这个场景里找到的所有 SKU 全选 |
| SKU | 就选这一个 |

每一层都要有**全选 / 反选**，而且父级勾选框要能显示「部分选中」的状态（勾了一半的场景，看起来不能和全选一个样）。**全选和全不选是同一个开关的两头，不并排放两个按钮**——勾满了按钮自己写「全不选」，再点一下就是全清。

你说的那个「选完不能取消」，根子在这一层的操作按钮是缺的——现在每行只有一个「以上全选」，没有任何取消的办法，只能回到那一行手动点掉。这一条和下面第 6 条是同一个问题。

### 6. 界面重做（这次最大的一块）

**现在到底差在哪**（我对着代码数过）：

1. 一个店的商品行大约 6 场景 × 16 个商品 × 30 条 ≈ **2900 行**，全挤在一列里，找东西全靠滚。
2. 商品角色是手风琴，**一次只能展开一个**——展开另一个，前一个自动收起。刚选完的东西一转眼就找不到了。
3. 只有「以上全选」，没有「本商品全选」「本场景全选」，也没有反选。
4. 选错了想撤回，只能回到那一行点掉；角色一收起就找不回去。底部「已选商品」只能看，**不能在那儿取消**。
5. 没有任何筛选。想只看有货的、或只看自己已经选的，做不到。
6. 勾选存在浏览器本地，清缓存就没了，界面上也不提示。

**改成什么**

- **三级勾选**：场景 / 商品角色 / SKU 各一个勾选框，右边写「已选 3 / 共 12」。父级勾上=全选，取消=全不选，勾一半显示半选。
- **每级一个「反选」**，加一个会自己换字的全选/全不选开关。
- **右边常驻一栏「已选清单」**：按场景分组，每行能直接取消，点一行能跳回左边它所在的位置；上面写总数和导出按钮。这样「已选」和「在选」不再是隔着几屏的两回事。
- **默认全部收起**：场景收成一行（场景名 + 已选/共），展开才渲染下面的内容；展开互不影响。
- **筛选条**：只看有货的 / 只看已选的 / 全部。
- **专业名词全换**（见下一条）。

要不要重做这一块，我的判断是：上面六个里有四个是**结构问题**（2900 行在一列、已选和挑选隔几屏），换颜色救不回来，得重新排。范围我建议就限在「场景与候选商品」和「已选」这两块，上传页和报告页不动。

这是这次改动最大的一块，比导出的工作量还大。

### 7. 界面去专业名词

按「只想看结果」的标准换一遍：

| 现在 | 换成 |
| --- | --- |
| 召回候选 SKU | 找到的商品 |
| 候选 / 候选数 | 可选商品 / 几个可选 |
| 主 SKU | 货号 |
| 商品角色 | 要用的商品 |
| 相关性复核 / 标相关·不相关 | 帮你复核了一遍 |
| 扩写商品检索词 | 补充搜索词 |
| 库存核验 | 查有没有货 |
| 采纳 | 已选 |
| TH / 目标国家 | 泰国（国家名） |
| RRF / 通道 / 融合 | （不出现） |

侧边栏那 8 个环节名也要跟着改一遍口语化的。

### 8. 扩写词默认不扩写

现在默认扩 6 个近义词。改成默认 **0**。

0 的时候，每个商品拿去检索的就是它自己那一个名字（中文一个、英文一个），不再让模型编一串近义词。这样：
- 找出来的商品更贴近你写的那一个，不会拉进隔壁品类
- 少一次模型调用，省钱也快一点

技术上还要补一句：现在是「设成 0 也照样调用模型，只是不要它扩」。改成 0 就直接跳过这一步，不调用。

### 9. 库存文件怎么更新

**答：每天给一个新的就够。** 具体是这样：

- 库存文件就是一个 Excel，程序每次跑「找商品」这一步时才去读它，读的时刻、文件的 SHA256 都记在那次结果里。
- 你把新文件放到位（路径不变的话不用改任何设置），下次跑「找商品」用的就是新的。
- **已经跑过的结果不会自己变。** 这是故意的：那张表上的数字对应的是哪一天的库存，得说得清。要换新的，点一下重跑「找商品」——这一步是本地算的，不花钱，几秒钟。这个按钮现在还没有，要加。

**新出现的主 SKU**：按你说的先不管。库存文件里有、但产品库里没有的主 SKU，程序直接跳过，不影响这一轮的匹配结果。也**不做任何清洗**——不加进产品库、不改名字、不猜它是什么。现在就是这样，不用改。

有一处要顺手加固：如果库存文件里某一行写的主 SKU 和产品库里的对不上（不是新商品，是两个文件打架），现在会让**整次匹配直接失败**。改成跳过这一行并记一条提示，不因为一行脏数据让整轮白跑。

### 10. 新增自定义产品（图二）

「识别到的商品」那一栏加一个按钮：填商品名（中英文）→ 直接进名单，参与后面的场景和找商品。

要处理的两件事：一是它和排除名单的关系（运营自己加的，不该被当成要排除的）；二是它没有截图依据，所以在报告里要能看出「这条是人工加的」。这个改动小，但很实用。
