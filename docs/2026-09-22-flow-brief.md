## 一、这个工具是干什么的

运营给一家跨境店铺做选品。他手上只有几张店铺截图，需要一份**能直接交给经理、能复制货号进 ERP 的 Excel**。

工具做的事：读截图 → 写这家店的经营判断 → 设计使用场景 → 列出每个场景要用的商品 → 去公司商品库（8 千多个货号）里把它们找出来 → 生成 Excel。

**最短路径只有三下：**

```
选择国家 + 传截图（或填商品名） → 点「开始生成」 → 点「导出 Excel」
```

一切设计都服务于这三下。中间的等待要有反馈，但**不能因为等待而多出任何一次点击**。

## 二、我要的流程

### 2.1 输入页

- 首屏只突出三样东西：**国家**、**截图或商品名**、**开始生成**按钮。
- **国家必须显式选择**（它决定「哪些货真的有货」）；店名选填、自动命名。
- 截图和商品名**二选一或都给**。没截图也能跑，只填商品名就行。
- 拖拽、粘贴、选文件共用一个上传区；缩略图能删、能放大。
- **参数也放在这一页**（见 2.4），默认折叠在「高级参数」里，从后端 schema 取默认值和范围。
- 主按钮**旁边**要写清交付物：「Excel 包含场景选品、主/子 SKU、店铺分析和去重清单」。让人提交前就知道能拿到什么。

### 2.2 提交之后：一个页面里发生三件事

提交后**不跳页**。进入一个持续更新的工作台，同一页里按顺序发生三件事。

**（1）等待**

- 用户只看见**四个主要阶段**：店铺分析 → 使用场景 → 场景商品 → 商品匹配。
  （后端实际跑八步，另外四步归入对应阶段，需要时可展开看细节。）
- 阶段没完成时，页面顶部（或右侧）有一块**深色区域**呈现资料汇聚的动效。
- **动画只服务于等待。** 它不是一个必须看完的过场，也不是庆祝效果。

**（2）阅读**

- **店铺分析一生成，动画立刻自动缩成顶部一条细进度链。**下方直接展开完整的六个章节，不需要点「查看分析」，不跳报告页，不开抽屉。
- 六个章节始终在同一页，用章节切换控制阅读长度。
- **后面召回还在跑，阅读不暂停任务。** 用户读他的，后台跑后台的。
- 分析内容用 `synthesis` 产物真的可读为准，**不做假百分比、不编剩余时间**。
- 刷新页面或重新打开已完成任务，直接展示已有分析，**不重播开场动画**。

**（3）导出**

- 文件就绪后**原位启用导出**，停留在用户正在读的位置，**不自动跳页、不抢焦点**。
- 桌面布局：中间左侧是分析或商品预览，**右侧常驻一张导出卡**。

### 2.3 导出卡

导出卡上永远有四样东西：

1. 文件名与格式（Excel）。
2. **导出范围**，默认「全部候选」，并显示计数：场景数、场景内去重条数、跨场景去重主 SKU 数。
3. 主按钮「**导出 Excel**」，文件能生成时立刻可用。
4. 次操作「**调整商品**」——选品编辑**不是必经的确认页**。

**范围只有三个：**

| 范围 | 含义 |
|---|---|
| 全部候选（默认） | 本次检索保留的候选全进文件。**不代表运营已采纳，也不代表系统保证合适**，所以复核状态必须随文件保留。 |
| 仅目标国家有货 | 按该次库存快照的明确有货状态选取。**未知不当成零库存。** 快照不可用时禁用并说明原因。 |
| 自选商品 | 用户按「场景 → 商品角色 → SKU」三层自己选。 |

**关键行为：**

- 点「全部候选」导出 = 明确指定导出这些候选，**不用逐行勾选**，也**不偷偷改写用户之前的自选名单**。
- 切换筛选视图**不修改**自选内容。
- 换范围**不触发模型重跑**，选择和页面内容都保留，方便换范围再导一次。

### 2.4 「调整商品」：三层板块，不是一个必经步骤

**「场景」和「这个场景召回的货号」是两个板块，不是一张大列表。** 中间用一条 2px 分隔线分开：

```
─────────────────────────────────────
使用场景
  [庭院烧烤  12 条] [周末露营  9 条] [阳台种植  7 条]   ← 卡片，选中态实底强调
─────────────────────────────────────  ← 2px
召回商品             当前：庭院烧烤 · 12 条
  图例：相关 / 不相关 / 未复核    复核只做标记，不剔除候选
  ┌────────┬──────────┬────────┬────────┐
  │ 货号   │ 名称     │ 角色   │ 库存   │
  └────────┴──────────┴────────┴────────┘
```

- 三层（场景 / 商品角色 / SKU）每一层都能勾选，每层有「全选 / 反选」。
- **全选和全不选是同一个开关的两头**，不并排放两个按钮——勾满了按钮自己变成「全不选」。
- 父级勾选框要能显示**部分选中**状态。
- **三层默认全部折叠，展开只渲染点开的那一个。**
- 筛选条：只看有货的 / 只看已选的 / 全部。
- 库存列写**国家名**（「泰国有货」），不写「目标国家」；未知写「未核验」，为零写「无货」，**都不与数字混淆**。

### 2.5 店铺列表与回到已完成的任务

- **店铺列表是入口。** 每家店一行：店名、国家、最近结果时间、**真实状态 + 对应动作**。
- 生成中的能看进度；有分析可读的能直接继续读；已完成的可打开导出；失败的能看原因并继续。
- **正式任务独立于当前页面运行**（关掉页面任务照跑）。
- 重新打开已完成的任务：默认展示商品清单，店铺分析作为同层次入口保留，**导出不要求切页签**。

### 2.6 异常时

| 情况 | 怎么做 |
|---|---|
| 处理失败 | 保留已生成的分析，显示原因和继续入口。**不能动画继续演到假成功。** |
| 范围内没有商品 | 禁用导出并提示换范围或选入商品。**不返回空的成功文件。** |
| 部分失败 | 不能显示「文件已准备好」。可导出就明确标「部分结果」并在文件里保留缺失说明。 |
| 重跑中 | 冻结当前结果版本。**不能把新场景和旧召回、旧库存拼在一起。** 版本隔离没做之前，运行中禁用新导出。 |
| 资料/参数变了 | 旧结果可查看，标「上次结果」。若允许导出旧结果，必须绑定它的参数和库存版本。 |

## 三、这套流程为什么这么设计

八条取舍，每条都有来处：

1. **最短路径优先。** 用户的主要任务是拿到能交付的 Excel，不是「读完一份报告」。所以导出永远可达，不藏在流程末尾。

2. **动画只服务于等待，不服务于成就感。** 分析一就绪，动画立即让位。用大画布把用户注意力锁住、逼他看完动画，是反目标。

3. **因果链不能跳。** 后台必须先形成经营判断（这家店靠什么赚钱），再生成场景和商品。跳过这一步省的是钱，赔的是选品质量。

4. **不假装知道。** 不做假百分比、不编剩余时间、不伪造 0 库存、不声称未知的有货、不把「未复核」说成「已通过」、不把「全部候选」说成「已采纳」。

5. **一按到底，中间没有确认站。** 参数放上传页，传完照片直接跑；商品名单在**结果页**增删改。任何「先让运营确认 X，再跑 Y」都是与这个姿态冲突的——**不要把它加回来**。

6. **场景和召回是两件事。** 场景是「这个情境需要什么」，召回是「库里哪几个货号能顶上」。合成一张列表会让人分不清哪一层在说什么。

7. **后台更新不打断前台阅读。** 任务推进时不改变用户正在读的章节、展开项和滚动位置。

8. **该省的钱省在阶段上，不省在界面上。** 改召回参数只重跑本地那几步（几秒钟、不花钱），**绝不隐式触发模型调用**。界面要让人一眼看出哪一步会花钱。

## 四、流程背后真实跑的八步

顺序写死在 `src/store_scenario_inspiration/app/jobs.py::STAGE_ORDER`，**前端不许自己排**。

| # | 代码名 | 界面上的说法 | 会调模型吗 |
|---|---|---|---|
| ① | `recognize` | 识别截图里的商品 | 会（没截图时不会，空跑） |
| ② | `clues` | 去掉你排除的商品 | 不会（纯本地） |
| ③ | `synthesis` | 写店铺结论和人群策略 | 会 |
| ④ | `scenes` | 生成使用场景 | 会 |
| ⑤ | `products` | 列出每个场景要用的商品 | 会（每场景一次，并行 4 个） |
| ⑥ | `expand` | 补充搜索词 | 会（默认 0 词 = 不调用） |
| ⑦ | `retrieval` | 找商品 | 不会（本地向量 + 关键词） |
| ⑧ | `rerank` | 帮你复核一遍 | **看谁复核**（Jev 极便宜 / DeepSeek 收费 / off 为零） |

**注意 ③ 在 ④ 前面**：先定这家店的产品结构和主力产品，再围绕它写场景。反过来（先自由生成场景、再事后总结）会让主力产品变成摆设。

**关于花钱，界面上不许出现「免费」「不花钱」这类词。** 统一由 `frontend/src/operatorUx.ts::stageNotice` 决定写哪句，不许另写一套：

- 会调模型的 → 「会调用模型，费用以当前服务配置为准。」
- 纯本地的 → 「按已保存的结果更新商品匹配。」

**进度是轮询，不是推流**（前端每 2 秒问一次 `GET /api/jobs/{id}`）。步骤少，运营感受不出差别，还省掉重连逻辑。**不要改成 SSE / WebSocket。**

## 五、我反复强调过的点（硬规矩）

这几条是踩过坑定下来的，**不是风格偏好**。

### A. 内容红线

1. **不引用市场消息、不写承诺、不写伪精确比例。** 不出现「市场正在增长」「建议保持 5:8 比例」「一定能提升转化」「下周就能上架」。公司没有市场数据来源，写市场规模/趋势/竞品就是在编。原话：「我们不负责承诺任何，我们只是去构思」。

2. **分析要写判断，不许复述截图。** 截图里有几个商品、卖了多少、出现在几张图上，运营在别处已经看得到。正文每一句都要往前推一步：这说明什么 / 问题在哪 / 下一步补什么。反面例子（线上真实结果）：「当前销售贡献主要来自厨房切割和地面清洁两个场景：不锈钢厨房剪刀（614件）和旋转拖把桶套装……」——纯复述，零判断。

3. **未来产品结构是最该写厚的一节：3–5 个方向，每个 3–4 句。** 四件事说全：从哪个主力产品长出来 / 现在缺什么 / 要补哪一类商品（品类层，不写货号品牌）/ 为什么站得住。理由只能从本店商品结构、截图销售证据、连带关系推，**不许引市场数据**。

4. **不要判断「店里有 / 店里没有」。** 截图只说明店铺**上架了什么**；产品库里有 8,126 个 SKU，很多是别处有没有上架的。场景只需照实写全需要的商品角色，**供应情况交给后面的检索环节回答**。

5. **禁止的用词**：「补货」「备货」「上架计划」（我们只分析现有产品，不做采购规划）、「覆盖度」「N/M 个是你家有的」「缺 K 样」、「打造完整链路」「提升连带销售」「强化类目专业度」这类空话。

6. **章节顺序**（按管理层阅读顺序）：执行结论 → 店铺画像 → 当前产品结构 → 人群 → 场景 → 未来产品结构 → 运营策略。

7. **「边界声明」和「依据」不上界面。** 数据里可能还留着这些字段（导出契约要用），但**一律不渲染**。原话：「图2这种话不用留，还有图三这种话也不要放」「图四里的依据啥的也不用放」。

### B. 界面红线

8. **长列表默认折叠，展开只渲染点开的那一个。** 三层（场景 / 商品角色 / 候选 SKU）都默认收起。展开一个场景下的一个商品，**不能把它的全部召回一起展开**——那是 8 场景 × 38 角色 × 50 行 ≈ 15,000 个 DOM 行，电脑会卡死。

9. **展开时页面不许跳动。** 唯一允许的滚动，是从右侧已选清单点回左边对应行。

10. **计数（已选 / 共 n）在折叠状态也要算得出来**，靠遍历数据算，不靠渲染 DOM。

11. **界面去专业名词。** 看的人只想看结果：

    | 不要用 | 用 |
    |---|---|
    | 召回候选 SKU | 找到的商品 |
    | 候选 / 候选数 | 可选商品 / 几个可选 |
    | 主 SKU | 货号（表头和文件里保留 SKU 字样方便复制） |
    | 商品角色 | 要用的商品 |
    | 相关性复核 | 帮你复核了一遍 |
    | 扩写商品检索词 | 补充搜索词 |
    | 库存核验 | 查有没有货 |
    | 采纳 | 已选 |
    | TH / 目标国家 | 泰国（国家名） |
    | RRF / 通道 / 融合 | 不出现 |

12. **「店铺方向」的最终权力在运营手上，不在截图。** 实测过：铺货型店铺 `Shopee-13021PH` 的 30 条线索**全部**被判成「商品卡片主图」，`confidence` 恒为 0.95，`evidence` 是同一句话——模型的角色标注在这类店铺上**根本没有分辨力**，自动分桶产出为零。所以：**别指望自动过滤，界面必须让「运营勾选方向」这一步醒目、好改。** 要区分两种情况——画面里的背景杂物（角色标注拦得住）vs 上架了但不对方向（只能靠运营）。

### C. 视觉红线

13. **「蓝色」要的是蓝，不是青。** 主色一律色相 195–230°。定稿值：

    | 用途 | 值 |
    |---|---|
    | 主色 | `#0a8fd4` |
    | 渐变亮端 | `#4fb9ec` |
    | 纸白上的正文/小字 | `#0a6396` |
    | **按钮上的深墨字** | `#03253d`（`#0a8fd4` 配白字对比度不足） |
    | 深色等待画布 | `#04223c` |

    蒂芙尼蓝 `#0abab5`（色相约 179°）在屏幕上读成**青绿**，整页会读绿，已经否掉一次。更早的扁平深蓝 `#3679d4` 也被否掉过，理由是「死板和土」。用户说「绿色」是批评，不是需求。

14. **正文至少 15px**；货号用等宽字体，库存数字右对齐，未知用文字而不是伪造的 0。

15. **细边框、分层表面、克制阴影。** 主按钮胶囊形 + 轻渐变 + 外发光；主次靠光影分，不靠颜色深浅分。

16. **深色等待画布是唯一的例外区域**：深蓝 `#04223c` + 缓慢流动的光场。分析生成后它收成顶部细条，正文恢复安静。正文跟随系统明暗主题。

17. **图形自绘**：纸片 / 小窗 / 方块 / 轨道 / 文件五种，共用统一的透光材质与阴影，不用通用图标库。按钮以文字为主，不堆装饰图标。

18. **动效细节**：主动切换分析章节约 220ms，阶段交接约 900ms。**没有庆祝遮罩、没有自动滚动、没有「必须播放完才能点」的按钮。** 全部动效必须在 `prefers-reduced-motion` 下停掉，但**正式任务推进不能依赖动画是否播放**。

19. **取消「所有内容都不能纵向滚动」的绝对限制。** 长表和低分辨率设备不能靠缩小文字塞满一屏。窄屏把导出操作放在内容之前，单列呈现，不把固定三栏等比缩小成不可读文字。

### D. 工程红线

20. **技术栈不许换**：FastAPI 后端 + React + TypeScript + Vite 前端 + **手写 CSS**。**不要再引入 Tailwind / shadcn / 动效库**——现在是手写 CSS，再叠一套原子类会变成两套样式系统并存，以后没人知道该改哪边。样稿里那些效果全部用原生 CSS + SVG + canvas 实现，不需要新依赖。

21. **流水线逻辑放在包里**（`src/store_scenario_inspiration/pipeline/`），`scripts/` 下的脚本只留薄壳。用户要的是高内聚低耦合，新阶段写进包，`app` 不许 import `scripts`。

22. **参数表的唯一来源是 `app/params.py::SearchParams`。** 这个 Pydantic 模型同时驱动后端校验和前端表单，界面文案（`description`）也从它派生。**前端不许另抄一份默认值和范围**，表单必须读 `GET /api/params/schema` 渲染。

23. **重排只标不剔除，也不做「捞回来」。** 默认 `mark_only`：模型只打标记，**一条都不删**。实测 `drop` 模式会把整个商品角色剔空（泰国店 3240 条里剔掉 2058 条），运营会因此看不到本该看到的候选。既然默认不剔除，**「显示被剔除候选的把握度 / 帮运营决定要不要捞回来」这类设计一律不做**。

24. **资产库口径是 8,126 个主 SKU**，不是设计规格里写的 1,750（那段已过时）。**界面不硬编码任何数量**，只显示 `load_products()` 实际返回的数字。池子大不是问题，不要主动「帮」用户收敛范围。库存更新走「**用现有产品去索引新库存数量**」，不重建产品资产。

25. **重排默认用 Jev**（TypeSafe），极便宜（约 $0.042/Mtok，只按输入计费；实测一家店 15,100 条候选约 $0.12）。端点 `POST https://api.typesafe.ai/v1/systemone`，模型 `jev-latest`，key 走环境变量，**不写进任何被 git 跟踪的文件**。

### E. 和我协作的方式

26. **凡涉及「怎么设计」的决策，先列出来对齐，再写代码。** 请求长什么样、传哪些字段、判定口径、参数默认值——这些要先讲清楚。纯实现细节（命名、循环写法、文件组织）不用问。原话：「反正全部涉及要怎么设计的你都和我沟通清楚，我来教你写代码，你不要在那里瞎写」。

27. **我给的业务意见是方向，不是规格。** 不要把它翻译成新的模块 / 新的 sheet / 新的字段。**先找现有的哪个字段或哪一段文字能承载它**——改提示词、改顺序、改摆放往往就够了。举例说明：「他们更倾向于店里卖得好的品作为主力产品」不是要新建「主力产品模块」，而是把主力产品写进「当前产品结构」那一节。

28. **解释任何东西时，先讲「这会影响什么结果」，再讲技术名词。** 不要默认我懂 RRF、向量检索、指纹。抛选项时，每个选项要写清楚**选了对业务意味着什么**。遇到「看不懂你说的那些问题是什么」，不要重复解释同一套说法，**改用真实数据和商品名跑一遍**。

29. **不要自作主张动我的浏览器做视觉验收**，我会自己打开看。前端做到「类型检查通过 + 接口能通」就算交付。

## 六、Excel 文件本身也属于产品设计

文件是最终交付物，不是副产品。当前约定：

| 工作表 | 内容 |
|---|---|
| 主 SKU 清单 | **场景横向分组**，一格一个货号（不塞在同一个单元格里），场景内去重，按该国有货数量降序。 |
| 子 SKU 清单 | 通过主 SKU 关联。**一行一个子 SKU**，子款全列，这个国家没货的写 0；查不到子款记录的主 SKU 也列一行并注明。 |
| 店铺概况 | 经营分析、场景等完整内容。 |
| 去重商品清单 | 跨场景货号去重，默认附带。 |
| **候选明细（新增提议）** | 场景、商品角色、主 SKU、名称、相关/不相关/未复核、库存状态。**理由**：默认提供「全部候选」快捷导出之后，接收文件的人也必须能区分候选质量，不能只在网页里看得见这些标记。 |
| 口径说明 | 参数、库存快照、复核说明。「哪个库存文件、什么时候读的、参数是多少」这些必须在。 |

**硬要求：**

- 主 SKU 那三列布局**不改**（经理要能整列复制进 ERP）。候选明细是**新增**一张表，不挤占它。
- **页面显示的范围、计数、预览，必须和实际 XLSX 的记录集合一致**；场景内去重和跨场景去重是两套口径，要分开。
- 导出过程**不重新调用模型**，换范围**不重跑分析**。
- 首版沿用现有 XLSX 导出器，**不引入新报表框架**。

## 七、更远的方向：场景创作台

工具现在是一条一次性流水线（进几张图，出一份报告）。**中期要演进成一个能反复调、反复试的「场景创作台」。**

三层的划分：

| 层 | 内容 | 状态 |
|---|---|---|
| **L1 输入层** | 截图识别 → 方向闸门（主营 / 存疑 / 排除）→ 外部信号（新闻、热搜，后续做） | 方向闸门待做 |
| **L2 创作层** | 场景生成。可调数量 / 风格 / 发散度，可反复再生成 | **全新** |
| **L3 落地层** | 扩写 → 召回 → 重排 → 采纳 | 已跑通，基本不动 |

**两个独立的旋钮，不要混为一谈：**

- **场景风格** = 给谁、什么时机用。预设：大众刚需 / 发散探索 / 季节性 / 节日 / 自定义。
- **产品周边度** = 场景里的产品离主营多远。核心（主营本体）↔ 周边（同场景配套）↔ 探索（相邻生活方式）。我明确要求过「可以进一步优化，更涉及周边一点」。

**迭代再生成**（这一条我很看重）：从已生成的场景里勾选产品当种子，再生成一次。这必须有**谱系树**（缩进展示第几代、基于哪些种子），否则生成几次之后没人记得场景是怎么来的。`frequency_penalty` / `presence_penalty` 就是为这一步准备的——不加惩罚，再生成会翻来覆去给差不多的东西；但调太高会让模型乱造商品名，所以给「保守 / 平衡 / 发散」三档预设，手调放高级设置。

**执行顺序：先修基调 + 基础界面，再做创作台。** 创作台盖在 L3 之上，而 L3 的方向闸门还没有、向量库还没启动——底座不稳，上面盖的要返工。

## 八、交给你的边界

**不能动的**：第四节那张八步表及其顺序、第五节全部硬规矩、第六节的文件口径、`params.py` 作为参数唯一来源。

**随意发挥的**：具体色值微调、圆角、阴影强度、间距；每个阶段用什么图形/动画表达；卡片里放多少信息；进度链放顶部还是右侧；结果页怎么排三层；上传页的视觉组织。样稿是**方向**不是**逐像素规格**——它演示了想要的感觉，不是让你照抄每一行 CSS。

**验收标准：**

- 输入资料后**一次提交**，任务结束后**一次点击**可下载全部候选文件，不要求展开场景或阅读报告。
- 店铺分析可读后**自动**缩小大动画，同页保留完整分析；后续召回继续，**不要求点击才能阅读**。
- 换导出范围**不触发模型任务**；切换视图**不丢自选记录**。
- 页面显示的范围、计数、预览与实际 XLSX 的记录集合**一致**；场景内 / 跨场景去重口径**分开**。
- 长列表默认折叠；键盘可操作；小屏不截断主按钮；减少动态效果后**无循环动画**。
- 界面上搜不到「免费」「不花钱」「市场趋势」「补货」「备货」这类词。
- 主流程的错误、取消、断连和缺少子款快照**均有可操作反馈**，不能动画继续演到成功。

**能自动验的：**

```bash
uv run pytest -q                  # 全绿，0 error
cd frontend && npx tsc --noEmit   # 类型必须过
node scripts/check_ui_proposal.cjs # 离线检查：配色色相、导出范围、去重计数等
```
