每个场景的每类产品占一行；主 SKU 作为检索索引、合并与展示单位，每种产品允许多个主 SKU 候选。具体子款选择由运营完成，结果不展示子 SKU。原始子 SKU 只保留在后台用于数据关联、清洗例外和库存追溯。任务标题显示国家，避免同一结果表混用国家。来源、评分、推理依据、版本和仓库明细保留在后台，经理默认不看。

每次都应覆盖适合这家店的基础需求场景，例如相关商品支持的日常收纳、做饭、通勤或桌面使用；这些场景不需要热点新闻支持。相关的当地热点只补充增量场景，没有合适热点时不强行生成，也不因新闻访问失败阻塞基础场景。基础/热点标签可用于内部去重，不增加经理结果列，不设置必须凑满的比例或固定场景数量。也不因 ERP 暂无产品而限制全部创意。缺少当地现货的产品可以留在 ERP 候选列，有货列如实为空。本阶段不输出利润预测、长篇机会分析或额外运营任务清单。

## 3. 库存规则

用户已确认：同国家不同销售员的库存可以共用。后台保留来源记录，不以销售员限制同国推荐。

对外按任务国家 + 主 SKU 判断：该国该主 SKU 下任一符合已确认推荐资格的明细 `海外仓可发 > 0`，即标该主 SKU 在该国有货。后台保留子 SKU 证据，但不替运营选颜色、规格等具体子款；“主 SKU 有货”不表示全部子款有货。不同国家不能互相补足。国家使用库存明确的 `国家` 字段，不从仓库名称猜测；支持 PH/菲律宾、TH/泰国、VN/越南、MY/马来西亚明确映射。

同国家/仓库/SKU 有 757 个重复键，常见为不同销售员记录。第一版只输出有没有货，使用存在性判断，不把重复记录的数量相加。`库存中心库存` 可能已经被订单锁定；`真仓库存` 明细全空，只有汇总有值，不能用于逐 SKU 判断。`本地海外仓可发` 与 `海外仓可发` 数值不同，本次不将两者相加；后续若公司使用另一字段，应明确修改口径。

有货不自动覆盖源系统中的禁售或风险状态。已选平台时按已有明确平台限制判断；平台未填时只能确认“目标国有可发记录”，不承诺完成全部上架资格检查。停产仍有货、配件独售、赠品独售分别确认，不默认等于无货或不可售。

```text
四列结果 → Excel/钉钉表格
```

现货1067个主SKU均已建立英文1024维Qdrant语义检索，完整ERP提供身份、名称、属性与英文关键词补充。该快照各国有货主SKU：PH436、TH256、VN282、MY126，跨国可重复；1315个不同子SKU只用于后台关联。暂不承诺全ERP全量向量召回。当前 `scripts/local_catalog.py` 一批词复用一次模型/SQLite连接；Qdrant常驻，但Python检索还不是常驻HTTP服务，worker/API和无人值守软重排尚待实施。光旅试跑已复用`soft_rerank`，完整候选留审计，经理表展示Codex判断同类、配套/替代、场景相邻的主SKU并标记分组。

现货召回应在国家可用范围内取 TopK，或持续补召回到足量本国候选；不能先取全库 Top20 再过滤国家，造成本国商品被截断漏掉。场景相邻、配套和替代商品保留，相关性通过排序体现；不新增随意的语义排除词。全 ERP 命中但本国无货的商品，在第四列留空。

库存每天导入用户提供的同格式完整快照，重算国家/主 SKU 有货集合，以成功导入的新快照替换旧快照，不把每日文件追加累加。新快照已明确变为零库存的记录必须及时撤销有货标记；新增、重新到货和消失的记录同步更新。首版通过每日导入完成，后续有已验证的下载接口再自动获取；本轮未创建定时任务。

库存更新不因数量变化重做产品embedding；新增或文本变化才补算。2026-09-16增加[产品增量更新入口](2026-09-16-incremental-update.md)：复用完整ERP基线，在日库合并子SKU，缺席行不删除，主SKU名称整理独立保存。同模型/策略复用Qdrant集合，只更新变化的稳定主SKU点；库存独立快照更新，已有商品不重算向量。CLI用单人串行锁，更新中断标记阻止混合版本检索，重跑`index-stock`恢复。按用户后续明确要求，个别缺失ERP档案的正库存主SKU单列原始明细，不阻断已匹配商品刷新；未知国家、身份冲突和国家覆盖变化仍报错保留旧库存，不能检测所有漏导。没有定时任务或自动下载。此处历史布尔“海外仓可发>0”不等于2026-09-16新增的数量口径，后者尚待独立汇总实现。

新选品任务绑定最新成功库存版本；历史场景可复用，历史结果中“有货主 SKU”可以用最新库存重新计算，不必重新识图或生成场景。库存日期显示在任务说明或页面状态，不增加四列业务结果。每日快照只表示导出时有货，不能冒充实时库存。

## 6. 批量截图、检索耗时与后续 API

2026-09-09 Windows 笔记本实测（Ryzen 7 5800H，16 GB RAM；可能同时有 Excel 审计负载）：

| 路径 | 实测 |
| --- | --- |
| 原 CLI 新进程混合检索：保温箱 / 便携榨汁机 | 3.565 / 3.256 秒 |
| 仪表化关键词新进程：三个词 | 1.524–1.638 秒 |
| 复用模型、SQLite连接和向量的单次混合查询 | 11.76–14.65 毫秒 |

模型/模块导入占了新进程大部分时间；每个词重新启动 Python 会浪费时间。模型和索引可以常驻；完整性检查在首次加载和索引切换时执行，不删除这些检查。上述样本较少，未清 OS 磁盘缓存，只测旧局部索引，不含 Codex 调度、图片识别、场景生成、联网或 API，不是完整系统 SLA。

同店图片分批提取后合并去重，再统一生成店铺场景；不同店任务独立，不把一个店的商品带进另一个店。同一任务内重复关键词只查一次，多个扩写词可批量向量化。按输入内容缓存有效提取结果，图片数量、识别失败和疑似重复均保留内部诊断。

现在由 Codex 承担理解图片、生成场景、扩写和软重排。后续保持相同任务输入/输出契约，将这一环节替换为实际验收通过的模型 API；图片和文本步骤可以选择不同模型。ERP/库存匹配仍由本地确定性代码执行；模型只能返回已有候选 SKU，输出需核验。

面向约100名运营的建议部署形态：钉钉或简单上传入口 + 一个Python API服务 + 有限并发worker + 持久任务表。任务/权限/状态可用PostgreSQL；商品检索复用SQLite FTS与已接入的Qdrant，embedding模型另行验收。当前仅本机127.0.0.1，不是团队部署；Windows可选payload索引创建失败，现货小集合使用服务内扫描过滤，扩容前要核验部署环境。100名用户不等于100个并发模型任务，按试点耗时、额度、费用设上限，不建微服务。

后台最小记录包括任务归属、国家、输入文件、进度、模型/提示词版本、ERP/库存版本、耗时和错误；重试只补失败步骤，重复提交可识别，模型密钥只在服务端。新闻摘要可以按国家/主题/有效期复用，不为每张图、每个SKU重复联网。无人值守API版本的完成时间、每店费用和吞吐须用真实店铺批次验证，本轮未测。

## 7. 热点信息源

用户要当地热点、生活方式与国际报道；普通天气变化不应被硬转成促销场景。先按国家和店铺类目筛选，问清“什么报道改变了谁的具体需求”，有用才进入场景。仅热度上升不等于销量上涨。

- [GMA News](https://www.gmanetwork.com/news/)：菲律宾本地新闻、生活方式、娱乐、体育等入口。官网可访问；RSS目录本轮一次请求返回403，不能据此承诺稳定自动采集。
- [Reuters Connect](https://reutersagency.com/content-delivery-platforms/reuters-connect/)：国际媒体与行业背景，官方有 API 与商业订阅；第一版使用可访问报道，自动全文/API使用需明确授权。
- [GDELT DOC API](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/)：发现多家媒体文章，可返回JSON/RSS；按事件地区与主题查找。sourcecountry是媒体所在地，不是事件所在地，不能漏掉国际媒体对当地的报道。检索结果不等于取得文章全文授权。
- [Google Trends](https://developers.google.com/search/apis/trends)：验证当地相关词的搜索关注变化；官方API目前为有限Alpha申请，初版用可访问网页或运营提供材料，不能依赖未获得的API权限。

本地语与英语词可互补，保存文章链接、发布时间、事件地区、观察时间和有效期。新闻转述同一来源时去重，过期事件不继续当作“当前热点”；新闻不可用时仍可根据店铺商品生成场景，不伪造热点。经理结果不增加这些后台字段。
