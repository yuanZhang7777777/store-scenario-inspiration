# METIS：以导出为终点的界面方案

状态：2026-09-22 的设计提案与可点击原型，尚未接入应用。原型使用明确标注的示例资料，不调用模型、库存库或导出接口。

## 1. 目标与取舍

用户的主要任务是拿到能交付、能复制货号、能按场景选品的 Excel。界面围绕这件事组织。

最短路径：**选择国家 + 截图或商品名 → 开始生成 → 导出 Excel**。

提交后进入一个持续更新的工作台。等待分析时展示动画；店铺分析一生成，动画自动缩成顶部进度链，分析直接在同一页展开。场景、商品需求和召回继续执行，文件就绪后原位启用导出。用户不必读完分析、逐条勾 SKU 或看完动画。

这里减少的是人的操作和等待焦虑，不承诺缩短模型推理时间。后台仍应先形成经营判断，再生成场景与商品。跳过这个因果链会损害选品质量。

## 2. 输入页与同页工作台

### A. 输入：告诉系统这家店卖什么

- 首屏只突出国家、截图/商品名、开始生成。
- 国家必须显式选择；店名选填、自动命名。商品名与截图可以二选一，也可同时提供。
- 拖拽、粘贴和选文件共用一个上传区；缩略图可删除、放大，提交前保留错误反馈。
- 高级参数默认折叠，继续从后端 schema 取默认值与范围。
- 输出说明紧挨主按钮：Excel 包含场景选品、主/子 SKU、店铺分析和去重清单，让人提交前就知道能拿到什么。
- **店铺列表是入口。** 每家店一行：店名、国家、状态（正在生成 / 分析已生成 · 正在匹配 / 文件已就绪，可导出 / 还没开始生成）、四段进度和小计数，动作按状态给——“打开工作台”“打开并导出”“开始生成”。等待期间停在这一页，行的状态自己会往前走，因为计时和后台任务不依赖当前在看哪个页面；已完成的任务优先显示“打开并导出”。相同资料不必重新上传。

### B. 等待与阅读：动画随产物让位

用户只看见四个主要阶段：店铺分析 → 使用场景 → 场景商品 → 商品匹配。识别、排除、扩写、复核归入相应阶段；八步详细状态仍可展开，顺序由后端决定。

**动画只服务于等待。** 分析尚未生成时，约 350px 高的深色区域呈现资料汇聚；分析生成后，这个区域自动收为约 150px 的顶部进度链。下方直接展开完整店铺分析及文件准备状态，无须点击“查看分析”，无须跳转报告页或打开抽屉。

整条链路始终在原位：已完成阶段缩小，当前阶段变宽，后续阶段保留弱化轮廓。四个节点不被四张互不相干的画布替换。分析出现后的后续动效都在小型进度链里运行，不重新展开大画布。

阶段、失败和完成由真实任务状态与产物就绪性驱动，不做假百分比或虚构剩余时间。分析以 synthesis 产物实际可读为准；召回和复核仍在后台运行，阅读不暂停任务。完成时启用同页导出按钮并提示，保留当前分析章节、展开项和滚动位置，不自动切到商品清单。

完整分析保留六类内容：经营判断、店铺画像、现有产品、拓展方向、目标人群、运营建议。用同页章节切换控制阅读长度，复用现有结果数据，不用几句摘要替代详细分析。刷新或重开任务也应根据已有产物直接展示分析，不重播开场。重跑时旧分析明确标“上次结果”，待新版本可读后再替换。

动效的四种语义：

| 阶段 | 动作 | 含义 |
|---|---|---|
| 店铺分析 | 截图、商品、国家沿流光汇入层叠报告纸片 | 多份信息形成一个判断 |
| 使用场景 | 报告节点缩小，场景节点接棒展开；光线向场景小窗发散 | 一个方向延展为多个生活情境 |
| 场景商品 | 场景节点缩小，商品节点扩展；分支连接成组商品方块 | 每个场景拥有自己的商品角色 |
| 商品匹配 | 两侧细密点流汇向召回核心，与前面的单向分支明显不同 | 多路搜索汇集具体货号 |

借鉴第一份参考的节点、细线和呼吸核心，借鉴第二份的粒子汇聚。技术使用现有 React、原生 CSS 与 SVG/canvas；不照搬附件里的安装说明、iframe 或登录界面。

背景是缓慢位移的蓝灰与青色光场，只存在于等待画布中，随画布一起缩小；正文使用稳定背景。自绘纸片、场景窗、商品方块、召回轨道和文件五种图形，共享透光材质与阴影，不使用通用图标库。采用原生 CSS 几何图形，清晰缩放且无需额外依赖。

流光长度按实际 CSS 像素固定，长路径只改变行程。原型以 requestAnimationFrame 驱动实际线段位移与背景移动；阶段尺寸以 CSS transition 过渡，避免只有静态连线。任务完成后停止循环。系统减少动态效果时停掉运动，阶段文字与分析仍可用；正式任务推进不能依赖动画是否播放。

### C. 同页导出：文件就绪即可带走

桌面布局：顶部店名/国家/结果版本与小型进度链，中间左侧分析或商品预览，右侧常驻导出卡。生成中先显示文件准备状态，文件可用时原位启用导出及范围选择，不自动跳页。

导出卡包含：

1. 文件名与 Excel 格式。
2. 导出范围，默认“全部候选”；显示场景数、场景内去重条数、跨场景去重主 SKU 数。
3. 主按钮“导出 Excel”，文件可生成时立即可用。
4. 次操作“调整商品”；选品编辑不是必经确认页。

范围只有三个：

- **全部候选**：本次检索保留的候选全部进入文件，不代表用户已采纳或系统保证适合；复核状态必须随文件保留。
- **仅目标国家有货**：按该次库存快照的明确有货状态选取，未知不当成零库存。快照不可用时禁用此范围，说明原因。
- **自选商品**：用户按场景、商品角色、SKU 三层选择；全选、取消、反选都保留。

点击“全部候选”范围的导出按钮，就是明确指定导出这些候选；不用逐行勾选，也不偷偷改写用户之前的自选名单。切换筛选视图不会修改自选内容。原来被 drop 模式剔除的记录不混入“全部候选”，不新增捞回流程。

等待期间左侧默认展示店铺分析；完成时保留用户所在章节。“商品清单”在可用时解锁，包含场景分组、货号、名称、库存。重新打开已完成的任务可以默认展示商品清单，店铺分析始终作为同层次入口保留，导出不要求切换页签。

**“场景”和“这个场景召回的货号”是两个板块，不是一张列表。** 上面一条浅色底：标题「使用场景」，每个场景一张卡片（场景名 + 货号条数），选中态用实底强调。一条 2px 分隔线之后是下面一条：标题「召回商品」，右侧写明当前是哪个场景、几条；再下一行图例说明相关 / 不相关 / 未复核的含义，并写清“复核只做标记，不剔除候选”；最后才是表格。行内商品名下挂角色与复核标记，库存未知写“未核验”、为零写“无货”，都不与数字混淆。自选模式复用同一套两条板块，展开层级放在下面一条里。

调整模式中三层默认折叠、按需渲染；展开不自动滚动，只有从已选清单跳回对应项时滚动。右侧导出卡始终保留。

## 3. 文件本身也属于产品设计

保留已实现的格式约定：

- 主 SKU 清单：场景横向分组，一格一个货号，场景内去重，按该国有货数量降序。
- 子 SKU 清单：通过主 SKU 关联，列子款及快照库存，未知明确写未知。
- 店铺概况：经营分析、场景等完整内容。
- 去重商品清单：跨场景货号去重，默认附带。
- 导出说明：参数、库存快照和复核说明。

**新增提议：候选明细工作表。** 保留场景、商品角色、主 SKU、名称、相关/不相关/未复核、库存状态。原因是默认提供“全部候选”快捷导出后，接收文件的人也必须区分候选质量，不能只在网页里看见这些标记。此表是新增需求；当前主 SKU 三列布局不改。

首版沿用现有 XLSX 导出器，不引入新报表框架。导出过程不重新调用模型，不因换范围而重跑分析。首次下载之后，选择和页面内容保持，方便换范围再次导出。

## 4. 视觉方向

- 纸白工作台、深墨文字，主色是明确的蓝，不是只在描边上点缀：实底按钮、选中态与阶段链用 `#0a8fd4` 的渐变（亮端 `#4fb9ec`），按钮文字改用深墨 `#03253d`（`#0a8fd4` 配白字对比度不足，撑不住正文）；纸白上的正文与小字用较深的 `#0a6396`；流光与外发光同样由 `#0a8fd4` 承担。深色等待画布是深蓝 `#04223c`。青色系不参与主色——`#0abab5` 这类蒂芙尼蓝在屏幕上是青绿，整页会读成绿色，因此不再使用。
- 细边框、分层表面、克制阴影；主按钮胶囊形、轻渐变与外发光。
- 等待画布采用深青（`#08272b`）与缓慢流动的光场；分析生成后收为顶部细条，正文保持安静。分析与表格跟随系统明暗主题，保证长时间阅读。
- 图形自绘为纸片 / 小窗 / 方块 / 轨道 / 文件，保留统一材质语言；按钮以文字为主，不堆装饰图标。
- 正文至少 15px；货号使用等宽字体，库存数字右对齐，未知用文字而非伪造 0。
- 桌面外壳可保持一屏，内容区按需滚动。取消“所有内容都不能纵向滚动”的绝对限制：长表与低分辨率设备不能靠缩小文字塞满一屏。
- 窄屏将导出操作置于内容之前，单列呈现；不把固定三栏画布等比缩小成不可读文字。

## 5. 与现状的差距

本次已核对 `StoresPage.tsx`、`StorePage.tsx`、`SceneWorkbench.tsx`、`app/main.py`、`app/export.py`。

| 当前实现 | 方案调整 |
|---|---|
| 按钮叫“生成经营建议” | 改为“开始生成”，旁边明确交付 Excel 的内容 |
| 经营分析在选品区域前面，页面较长 | 分析生成即原位展示六个章节，后续进度缩顶；商品清单同页切换，导出卡持续可见 |
| 未勾选商品时导出禁用 | 全部候选/有货范围可直接导出，自选范围仍要求至少选一项 |
| 三组文字进度 + 八步详细日志 | 保留完整进度链；已完成节点缩小、当前节点展开；分析生成后全链缩顶，并保留八步真实诊断 |
| 选择只保存在当前浏览器 | 首版明确保留限制；跨设备继续选择需后端持久化，另列后续工作 |
| 导出端点读取 picks + dedupe，返回 XLSX | 用选定范围构建 picks 复用；若数据量实测较大再改服务端范围参数 |
| 导出缺少子款快照时直接 409 | 页面提前显示导出就绪性和“补齐商品与库存”操作，避免最后一步才失败 |
| 文件主要清单无逐条相关度列 | 增加候选明细，不挤占现有主 SKU 三列布局 |

交接稿中“导出 csv | sku | cn”与当前接口不符：当前接口实际返回 XLSX；复制货号属于前端独立动作。实现时以核验后的现有代码为基线。

## 6. 异常与数据一致性

- 部分失败不能显示“文件已准备好”。如果已有足够产物可导出，应明确标“部分结果”，并在文件内保留缺失说明；当前接口未完整支持此能力，首版不伪造成功。
- 重跑时冻结当前结果版本；导出不能把新场景与旧召回、旧子款库存拼在一起。未实现版本隔离前，运行中禁用新导出，完成后再开放。
- 资料或参数有变化，旧结果可以查看，页面标明“上次结果”。若允许导出旧结果，必须绑定其参数/库存版本；不能用刚保存的参数描述旧文件。
- 无候选时不给空白“成功文件”，说明哪个场景/角色没匹配到，提供调整范围或重试入口。
- 库存未知不声称有货；未复核不声称已通过；不把所有候选称为“已采纳”。
- 后台状态更新不改变用户正在阅读的章节、展开项和滚动位置；完成时提示并启用导出，不自动跳页或切换页签。

## 7. 实施顺序与验收

**第一批：同页等待、阅读与导出。** 按产物就绪性渐进展示分析，保留详细分析组件，顶部连续进度链自动收缩；常驻导出卡、三个导出范围和导出就绪性，复用现有 XLSX 逻辑并补候选明细。

**第二批：完善视觉与等待动效。** 精简输入页，加入自绘图形、背景光场和四种流程运动，按真实状态推进，不给动画设置必须播放完的时长。完善失败、取消、重试和减少动态效果。

**第三批：用真实任务测耗时。** 分开记录模型处理、检索复核、浏览器交互和 XLSX 生成时间，再决定预生成文件、任务级缓存、按场景提前导出等投入。首版不为潜在需求增加队列系统或新依赖。

验收：

- 输入资料后一次提交，任务结束后一次点击可下载全部候选文件，不要求展开场景或阅读报告。
- 店铺分析可读后自动缩小大动画，同页保留完整分析；后续召回继续，不要求点击才能阅读。
- 阶段推进保留四个流程节点；任务完成后只启用导出，不能打断阅读、抢焦点或自动换页。
- 换导出范围不触发模型任务；切换视图不丢自选记录。
- 页面显示范围、计数、预览和实际 XLSX 的记录集合一致；场景内/跨场景去重口径分开。
- 全部候选文件包含复核与库存状态；自选文件只含自选集合。
- 长列表默认折叠；键盘可操作；小屏不截断主按钮；减少动态效果后无循环动画。
- 主流程错误、取消、断连和缺少子款快照均有可操作反馈，不能动画继续演到成功。
- 使用真实数据回归 `uv run pytest -q`、`npm test`、`npm run build`，检查导出文件与页面一致。

## 8. 本次交付边界

交付设计方案及 `2026-09-22-export-first-prototype.html` 交互示意。默认从等待开始，约 8 秒自动展开分析并缩小顶部链路，接着生成场景、商品需求、匹配商品，约 40 秒后原位启用模拟导出。演示控制可暂停、重播或跳到下一阶段；这些压缩时长和演示控制不属于正式产品。分析有六个章节，可在后台推进期间自由阅读；导出保留三种范围、商品调整与模拟动作。所有货号、库存和分析均为示例。

当前应用、接口、参数和真实店铺数据未改动。离线检查命令：`node scripts/check_ui_proposal.cjs`，覆盖脚本/CSS 语法、导出范围、去重计数、选择保留、分析提前就绪、阶段边界、连线几何与元素引用。用户要求不操作其浏览器，本次不声称完成浏览器视觉与交互验收。
